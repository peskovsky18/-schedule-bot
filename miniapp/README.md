# Расписание — Telegram Mini App

Веб-приложение с расписанием занятий: открывается прямо в Telegram.
Статика живёт на Netlify, данные отдаёт бот на Render через `/api/schedule`.

## Как это устроено

```
Telegram  →  Netlify (этот каталог)      — HTML, CSS, JS
                    │
                    └── fetch  →  Render (bot.py)  — /api/schedule (JSON)
                                        │
                                        └── guide.herzen.spb.ru
```

Парсер расписания остаётся **один** — на Python, в `parser.py`. Мини-приложение
его не дублирует, а только рисует полученный JSON.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Разметка |
| `assets/css/styles.css` | Стили, подхватывают тему Telegram |
| `assets/js/config.js` | **Адрес API и настройки скримера** |
| `assets/js/core.js` | Чистая логика: даты, склонения, режимы. Тестируется в Node |
| `assets/js/app.js` | Сеть, кэш, отрисовка, скример |
| `assets/img/scare.jpg` | Картинка для скримера — **замените своей** |
| `netlify.toml`, `_headers` | Заголовки и кэширование |

## Вкладки

**Сегодня** · **Завтра** · **Неделя** · **Следующая** · **Всё**

«Неделя» — ближайшие 7 дней от сегодня. «Следующая» — следующее окно из
семи дней (с +7 по +13), встык: окна не пересекаются и не оставляют
пропусков. «Всё» — все дни, что есть в данных.

## Скример (розыгрыш)

Через 30 секунд после открытия приложения на весь экран появляется
картинка. Закрывается крестиком, тапом в любом месте или сама через
3 секунды.

Настройки в `assets/js/config.js`:

```js
window.SCREAMER = {
  enabled: true,      // false — выключить совсем
  delayMs: 30000,     // через сколько показать
  durationMs: 3000,   // через сколько закрыть автоматически
  image: "assets/img/scare.jpg",
  fit: "cover",       // "cover" — на весь экран с обрезкой краёв,
                      // "contain" — фото целиком, с чёрными полосами
};
```

`fit` стоит переключать, если картинка альбомная: при `cover` на телефоне
в кадр попадает примерно 40–45 % ширины фото, при `contain` оно видно
целиком, но мельче.

Файл `assets/img/scare.jpg` — заглушка с подсказкой. **Замените её своей
картинкой**, сохранив имя, либо укажите другой путь в `image`.
Рекомендации: JPG или WebP, примерно 1080×1920, до 300 КБ — картинка
загружается заранее, чтобы появиться мгновенно.

Что сделано намеренно и почему:

- **Нет звука.** Внезапный громкий звук может навредить человеку
  с больным сердцем или испугать сильнее, чем вы рассчитываете.
- **Нет вспышек и стробоскопа.** Резкие мигания провоцируют приступы
  у людей с фотосенситивной эпилепсией. Появление — короткое плавное
  затухание прозрачности, не более.
- **Крестик в правом верхнем углу** и закрытие тапом в любом месте:
  человек всегда может прекратить это мгновенно.

Если будете добавлять звук или мигание — это уже другой уровень риска,
и я бы не советовал.

## Плеер

Внизу экрана — полоса с одной дорожкой: play/pause, название,
перемотка нажатием по полосе и счётчик времени.

Настройки в `assets/js/config.js`:

```js
window.PLAYER = {
  enabled: true,                            // false — убрать плеер
  src: "assets/audio/franse.mp3",
  title: "Voskresenskii — Франсе (prod. By Wipo)",
};
```

Файл лежит в `assets/audio/franse.mp3`. Имя специально из ASCII:
пробелы, кириллица и скобки в URL требуют кодирования и легко ломаются.
Свой файл кладите туда же и меняйте `src` — либо перезапишите
`franse.mp3`, сохранив имя.

Как это устроено:

- **`preload="none"`** — файл скачивается только после нажатия play,
  поэтому дорожка не влияет на скорость открытия приложения;
- **автовоспроизведения нет** — мобильные WebView всё равно блокируют
  звук до касания экрана;
- **файл кэшируется на сутки** (в отличие от кода приложения), так что
  повторное прослушивание не тратит трафик. Это единственный ресурс
  сайта с настоящим кэшем: он большой и меняется редко. Если замените
  файл, а у людей останется старый — измените имя файла и `src`;
- **перемотка работает** благодаря поддержке Range-запросов у Netlify.

### Про авторские права

Дорожка — коммерческая запись. Сайт публичный и без пароля, то есть вы
фактически раздаёте её всем, у кого есть ссылка. Для учебного проекта
риск невелик, но если сайт станет заметным, Netlify может получить
жалобу и снять сайт. Безопасная альтернатива — royalty-free музыка
или ссылка на легальный источник вместо файла.

### Обязательно: отключите плашку Netlify

Netlify добавляет в правый нижний угол плашку «Powered by Netlify». Она
позиционируется как `fixed` с максимальным `z-index`, **видна всем
посетителям** и перекрывает низ экрана: обрезает название трека и делает
некликабельной правую половину полосы перемотки.

Отключается за полминуты, передеплой не нужен:

**Project configuration → General → Powered by Netlify badge → выключить**

Изменение применяется к следующему запросу. На бесплатном тарифе
плашка включена по умолчанию для проектов, созданных после 19 августа
2026 года.

## Шаг 1. Узнать адрес API

Разверните бота на Render (см. корневой `README.md`) и скопируйте адрес
сервиса, например `https://schedule-bot-a1b2.onrender.com`.

Проверить, что API отвечает:

```bash
curl https://schedule-bot-a1b2.onrender.com/health
```

Первый запрос может занять до минуты — бесплатный Render просыпается.

## Шаг 2. Указать адрес в config.js

```js
window.SCHEDULE_API_BASE = "https://schedule-bot-a1b2.onrender.com";
```

Без слэша на конце. Адрес можно переопределить и без правки файла —
параметром в ссылке (удобно для проверки):

```
https://ваш-сайт.netlify.app/?api=https://schedule-bot-a1b2.onrender.com
```

## Шаг 3. Опубликовать на Netlify

### Вариант А — из Git (обновляется автоматически)

1. [app.netlify.com](https://app.netlify.com) → **Add new site → Import an existing project**.
2. Выберите GitHub и репозиторий `-schedule-bot`.
3. **Base directory: `miniapp`** — это важно, иначе Netlify опубликует корень
   репозитория с Python-кодом.
4. Build command оставьте пустым, publish directory — `.` (уже задано в
   `netlify.toml`).
5. **Deploy**.

### Вариант Б — перетаскиванием (быстрее, без Git)

1. [app.netlify.com/drop](https://app.netlify.com/drop).
2. Перетащите **папку `miniapp`** целиком.

При таком варианте настройки из `netlify.toml` не применяются, поэтому
заголовки продублированы в файле `_headers` — он работает в обоих случаях.

## Шаг 4. Подключить к Telegram

Нужен бот-владелец приложения. Проще всего — автоматически: укажите на Render
переменную `MINIAPP_URL` с адресом Netlify, и бот при старте сам поставит
кнопку меню «Расписание». Если она не появилась, перезапустите сервис
(**Manual Deploy → Restart**).

Вручную через [@BotFather](https://t.me/BotFather):

1. `/mybots` → выберите бота → **Bot Settings** → **Menu Button** →
   **Configure menu button** → вставьте адрес Netlify.
2. Либо `/newapp`, если хотите отдельное приложение со своей иконкой и
   короткой ссылкой вида `https://t.me/ваш_бот/имя_приложения`.

**Требование Telegram: адрес должен быть HTTPS.** `netlify.app` подходит.

## Локальный запуск

```bash
# 1. API (из корня репозитория)
TOKEN=123456:TEST PORT=8201 python bot.py

# 2. Статика
cd miniapp && python3 -m http.server 8202
```

Откройте `http://localhost:8202/?api=http://127.0.0.1:8201`.

Приложение работает и вне Telegram — SDK подключается только если доступен,
поэтому его удобно отлаживать в обычном браузере.

## Особенности

- **Кэш в localStorage.** Бесплатный Render засыпает, поэтому при открытии
  сразу показывается последнее сохранённое расписание, а свежее
  подгружается в фоне. При отсутствии связи выводится предупреждение,
  но расписание остаётся на экране.
- **Время по Москве.** «Сегодня» и «Завтра» считаются по `Europe/Moscow`,
  а не по часовому поясу телефона, — иначе расписание разъезжалось бы
  у тех, кто уехал или сменил пояс.
- **Кэш не более 5 минут** (`CACHE_TTL` в `parser.py`). Кнопка обновления
  в шапке запрашивает данные заново.
- **Ссылки на Moodle** открываются через `Telegram.WebApp.openLink`,
  иначе внешний сайт открылся бы внутри webview и приложение «потерялось».
- **Тема** берётся из `themeParams`, есть светлый и тёмный вариант.
