# Расписание — Telegram Mini App

Веб-приложение с расписанием занятий: открывается прямо в Telegram.
Статика живёт на Netlify, данные отдаёт бот на Render через `/api/schedule`.

## Как это устроено

```
Telegram  →  Netlify (этот каталог)      — HTML, CSS, JS
                    │
                    └── fetch  →  Render (bot.py)  — /api/schedule (JSON)
                                        │
                                        └── сайт учебного заведения
```

Парсер расписания остаётся **один** — на Python, в `parser.py`. Мини-приложение
его не дублирует, а только рисует полученный JSON.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Разметка |
| `assets/css/styles.css` | Стили, подхватывают тему Telegram |
| `assets/js/config.js` | **Название приложения, адрес API, настройки плеера, рулетки и шахмат** |
| `assets/js/core.js` | Чистая логика: даты, склонения, режимы. Тестируется в Node |
| `assets/js/chess.js` | Разбор FEN и координаты клеток. Тестируется в Node |
| `assets/js/app.js` | Сеть, кэш, меню, доска, музыка, отрисовка |
| `netlify.toml`, `_headers` | Заголовки и кэширование (для Netlify; GitHub Pages их не читает) |

## Вкладки и меню

Название в шапке — **ППРСД super app**. Раньше там стояли номер группы
и институт, но они занимали две строки, а группа всё равно одна и та же.
Название задаётся в `config.js` (`window.APP.title`).

В верхней панели — три режима:

| Режим | Где |
|---|---|
| Сегодня | вкладка |
| Завтра | вкладка |
| Следующая неделя — календарная, понедельник–воскресенье | вкладка |
| Неделя — 7 дней от сегодня | меню → Расписание |
| Всё расписание — все дни из данных | меню → Расписание |

**«Следующая неделя» считается от понедельника.** Расписание в вузе
недельное, и неделя начинается в понедельник, поэтому блок показывает
следующую календарную неделю целиком: с понедельника по воскресенье.

Раньше это было окно «сегодня плюс 7 … плюс 13 дней», и оно начиналось
с того же дня недели, что и сегодня: в среду «следующая неделя»
начиналась со среды. Если сегодня понедельник, блок показывает
понедельник через неделю — текущая неделя ещё идёт.

За это отвечает `startOfNextWeek` в `core.js`; проверены переходы через
границу месяца, года и високосный день.

**«Неделя» осталась окном «семь дней от сегодня»** — это взгляд «что
дальше». Поэтому две вкладки пересекаются на один день, когда «Неделя»
захватывает понедельник следующей недели. Это осознанно: вкладки
отвечают на разные вопросы. Если хотите, чтобы «Неделя» тоже была
календарной (понедельник–воскресенье текущей недели), это правка
в одной строке — скажите.

Когда режим выбран из меню, вкладки в панели не подсвечиваются — это
разные представления. Активный пункт виден при открытии меню.

**Меню открывается на весь экран.** Разделов стало много, и в узкой
колонке 330 px они не помещались: треки обрезались, а доска была мелкой.
На широком экране (например, в Telegram Web) ширина ограничена 560 px,
иначе панель растянется на весь монитор.

Меню делится на две группы:

- **Расписание** — «Неделя» и «Всё расписание»;
- **Приколы** — шахматы, рулетка и **ППРСД music**.

«Приколы» **свёрнуты по умолчанию** и раскрываются нажатием на заголовок.
Иначе меню тонуло в развлечениях, а расписание приходилось искать.
Состояние не запоминается: при следующем открытии раздел снова свёрнут,
и это осознанно — иначе смысл прятать теряется.

Свёрнутость связана с опросом шахмат: пока раздел закрыт, доска не видна,
и приложение не тратит запросы к Upstash. Как только раздел раскрыт
и меню открыто — состояние обновляется сразу.

Меню на весь экран означает, что фон под ним недоступен: закрыть можно
крестиком, клавишей Escape или выбором пункта расписания.

## Техподдержка

Внизу главной страницы — неприметная кнопка «Техподдержка» (текст
с прозрачностью 0.45). По нажатию появляется сообщение
«Поддержки нет. Живите так.» с крестиком; закрывается крестиком
или клавишей Escape.

Ширину сообщения задавать явно обязательно: при одном только
`left: 50%` браузер отводит элементу место лишь до правого края, и текст
переносился на две строки без нужды. Это проверяется в браузерном тесте.

## Добавление музыки

В разделе **ППРСД music** есть кнопка «Добавить трек»: можно выбрать файл
с телефона или вставить ссылку на mp3. Добавленные треки видны всем и
играются наравне со встроенными.

**Где хранится звук.** Мини-приложение статическое — файлы ему хранить
негде. Поэтому загрузка идёт на сервер, а оттуда в Redis (Upstash)
в base64. Новых сервисов не потребовалось.

**Почему предел 6 МБ.** Он взят из живого замера, а не назначен на глаз:
Upstash отвечает `HTTP 413` на тело длиннее 10 485 760 байт. Base64
раздувает данные примерно на треть, поэтому файл ограничен шестью
мегабайтами — это восемь в base64, с запасом до потолка. Число приходит
клиенту с сервера (`maxUploadBytes`), чтобы не жить в двух местах.

**Кто может удалять.** Автор — свои треки, администратор (`ADMIN_ID`) —
любые. Удаление в два нажатия: системное окно подтверждения в WebView
Telegram может не показаться вовсе, и удаление просто не сработало бы.

**Проверка подписи** обязательна для загрузки и удаления: иначе общее
хранилище забьёт кто угодно. Отдача аудио, наоборот, без подписи — тег
`<audio>` не умеет отправлять заголовки. Идентификаторы случайны
(10 символов), поэтому перебором чужой трек не найти.

**Перемотка** работает: сервер поддерживает `Range` и отвечает `206`.
Без этого браузер не даёт двигать ползунок.

Ограничения, о которых стоит помнить:

- бесплатный Upstash даёт 256 МБ и 10 000 команд в сутки. Звук читается
  и пишется командами, так что при активном слушании лимит не бесконечен;
- список и звук лежат в разных ключах, но список перезаписывается целиком.
  Если двое добавят трек в одну и ту же секунду, один может потеряться.
  Для группы из нескольких человек это несущественно;
- чужие ссылки живут, пока жив чужой хостинг. Файл надёжнее.

## ППРСД music

Кнопка меню — в правом верхнем углу шапки, рядом с кнопкой обновления.
Меню выезжает справа и содержит:

- **Расписание**: «Следующая неделя» и «Всё расписание» — переключают
  вкладку на основной странице и закрывают меню. Открытый раздел
  подсвечивается.
- **Треки**: список дорожек со встроенным плеером.

Плеера внизу экрана нет: треки живут только в меню. Нажатие на трек
запускает его, повторное нажатие на текущий ставит паузу. У текущего
трека видны полоса прогресса и счётчик времени. **Воспроизведение
не прерывается при закрытии меню** — звук продолжает играть, а чтобы
поставить паузу, нужно открыть меню снова.

Меню закрывается крестиком, кликом по затемнению или клавишей Escape.

Настройки в `assets/js/config.js`:

```js
window.PLAYER = {
  enabled: true,               // false — убрать плеер
  tracks: [
    { title: "Voskresenskii — Франсе (prod. By Wipo)",
      src: "assets/audio/franse.mp3" },
    { title: "Voskresenskii — Стиралка (prod. By Wipo)",
      src: "assets/audio/stiralka.mp3" },
  ],
  autoNext: false,             // true — играть следующий по окончании
  rememberLast: true,          // открывать на треке, который слушали
};
```

Поддерживается и старый формат с одной дорожкой — вместо `tracks`
можно указать `src` и `title`.

Файлы лежат в `assets/audio/`. Имена специально из ASCII: пробелы,
кириллица и скобки в URL требуют кодирования и легко ломаются.
Свои файлы кладите туда же и добавляйте в `tracks`.

Как это устроено:

- **`preload="none"`** — файл скачивается только после нажатия play,
  поэтому общий вес дорожек не влияет на скорость открытия приложения;
- **автовоспроизведения нет** — мобильные WebView всё равно блокируют
  звук до касания экрана;
- **`autoNext` выключен по умолчанию**: трек заканчивается — плеер
  останавливается;
- **аудио кэшируется на сутки** (в отличие от кода приложения), так что
  переслушивание не тратит трафик. Это единственный ресурс сайта
  с настоящим кэшем: он большой и меняется редко. Если замените файл,
  а у людей останется старый — измените имя файла и `src`;
- **перемотка работает** благодаря поддержке Range-запросов у Netlify.

### Про авторские права

Треки — коммерческие записи. Сайт публичный и без пароля, то есть вы
фактически раздаёте их всем, у кого есть ссылка. Для учебного проекта
риск невелик, но если сайт станет заметным, Netlify может получить
жалобу и снять сайт. Безопасная альтернатива — royalty-free музыка
или ссылка на легальный источник вместо файлов.

### Если вернётесь на Netlify: отключите плашку

Netlify добавляет в правый нижний угол плашку «Powered by Netlify». Она
позиционируется как `fixed` с максимальным `z-index`, **видна всем
посетителям** и перекрывает низ экрана: обрезает название трека и делает
некликабельной правую половину полосы перемотки.

Отключается за полминуты, передеплой не нужен:

**Project configuration → General → Powered by Netlify badge → выключить**

На GitHub Pages такой плашки нет, поэтому приложение от неё не страдает.
Код, который её обходил (`watchNetlifyBadge` в `app.js` и отступы по
`body.has-netlify-badge`), оставлен: он безвреден, когда плашки нет,
и снова заработает при возврате на Netlify.

## Казино

Раздел «Казино» в «Приколах»: однорукий бандит на бесплатные тугрики.
Три барабана, ставка 10, 25, 50 или 100, выплата за три одинаковых
от ×4 до ×80.

**Тугрики считает сервер, и это не придирка.** Если баланс и результат
прокрута определять в браузере, любой откроет консоль и нарисует себе
сколько угодно тугриков — а весь смысл игры в том, что выигрыш случаен.

### Как получают тугрики

| Когда | Сколько |
|---|---|
| Первый вход за сутки | 500 |
| Воскресенье, если заходили семь дней подряд | ещё 3000 |
| Заходили, но пропустили день | серия начинается заново |

Монеты начисляются **при запуске приложения**, а не при открытии раздела:
«за вход в мини-апп» — это и есть вход. Сервер сам решает, положено ли
что-то сегодня, поэтому повторный запрос безвреден: отметку о входе
не нужно хранить на клиенте, где её легко потерять.

Сутки считаются по Москве. Иначе у человека, зашедшего в 23:50,
следующий день начинался бы через десять минут.

### Ставка

Готовые суммы (10, 25, 50, 100) — для быстрого выбора, а рядом можно
ввести **свою**. Она зажимается в границы `MIN_BET`…`MAX_BET`
в `casino.py`; границы приходят клиенту вместе с состоянием, поэтому
подсказка в поле всегда совпадает с тем, что примет сервер.

Сверх баланса поставить нельзя: прокрут отклонится с объяснением.

### Разовый подарок

При первом входе каждому начисляется **2009 тугриков** и показывается
уведомление с текстом подарка.

**Подарок версионный.** В записи хранится `giftTaken` — идентификатор
последнего полученного подарка. Стоит поменять `GIFT_ID` в `casino.py`,
и подарок выдаётся заново всем: и новым игрокам, и тем, кто брал
прошлый. Текст уведомления задан там же, рядом.

### Таблица выплат

| Три одинаковых | Выплата |
|---|---|
| 🥔 картошка | ×4 |
| 🥒 огурец | ×6 |
| 🧦 носок | ×10 |
| 🐸 жаба | ×18 |
| 🚽 унитаз | ×35 |
| 💩 какашка | ×80 |
| Две одинаковые | возврат ставки |

**Возврат 85.3%** — измерено симуляцией на 200 000 прокрутов, а не
назначено на глаз. Это уровень настоящих автоматов (обычно 85–96%).
Проверяется тестом: если таблицу поменять, тест это заметит.

Случайность берётся из криптографического источника. Обычный
`Math.random` даёт предсказуемую последовательность, а тут важно, чтобы
результат не зависел от предыдущих прокрутов.

## ППРСД shop

Раздел в меню, отдельно от «Приколов»: обмен тугриков на подарки.
Товар один — подарочная карта «Золотое Яблоко» на 300 ₽ за 30 000
тугриков.

**Покупка — это перевод.** Тугрики списываются у покупателя и
зачисляются администратору, поэтому общее количество не растёт.
Заказ сохраняется в хранилище: даже если уведомление в Telegram
не уйдёт, покупка не потеряется.

Покупатель указывает **имя и контакт** — по ним администратор
передаёт карту. Без них покупка не проходит: заказ некому передать.

Администратору приходит сообщение в бот с товаром, именем, контактом
и ссылкой на покупателя.

### Секретный пароль

Под кнопкой «Техподдержка» есть еле заметная точка. По нажатию
раскрывается поле пароля: верный пароль даёт **100 тугриков**.
Ограничения на количество раз нет — сколько введёте, столько
и начислим.

**Пароль проверяет сервер.** Если бы сверял браузер, любой посмотрел бы
исходники страницы, увидел там ответ и получил тугрики даром — секрет
превратился бы в кнопку «дай тугриков».

**В коде лежат только SHA-256**, не сами пароли: репозиторий публичный,
и открытый текст увидел бы каждый. Регистр и пробелы по краям не важны.

**Паролей может быть несколько, и каждый даёт свою сумму.** Они
перечислены в `PROMOS` в `casino.py`: ключ — хеш, значение — сколько
тугриков. Чтобы добавить пароль, посчитайте от него SHA-256
в нижнем регистре и допишите строку.

Если задать переменную окружения `PROMO_PASSWORD`, она важнее списка:
работает только она и даёт `PROMO_COINS`. Так пароль можно держать
вне репозитория.

### Мелочи, о которых стоит знать

- Ставка запоминается и в браузере, и на сервере.
- Два одновременных прокрута могли бы прочитать один баланс, и за две
  игры списалось бы как за одну. От этого стоит замок на пользователя.
- Баланс не уходит в минус: прокрут при нехватке тугриков отклоняется.
- Клиент только показывает то, что вернул сервер. Барабаны мелькают
  полторы секунды, чтобы результат не выглядел мгновенной подделкой,
  но сам результат считается до анимации.

## Рулетка

Раздел «Рулетка» в меню: колесо с секторами «идти на пары» и «не идти».
Кнопка «Крутить» запускает прокрутку, через пару секунд выпадает исход.

Настройки в `assets/js/config.js`:

```js
window.ROULETTE = {
  enabled: true,
  spinMs: 2600,          // длительность прокрутки, мс
  outcomes: [
    { symbol: "🎓", title: "Идти на пары", short: "Идти", tone: "go", color: "#2fb27c" },
    { symbol: "🛋️", title: "Не идти", short: "Не идти", tone: "skip", color: "#e0574f" },
  ],
};
```

Секторов может быть сколько угодно: колесо делится поровну, цвет берётся
из `color`, надпись внутри сектора — из `short`, а `symbol` и `title`
показываются в результате. `tone: "skip"` красит результат в красный,
всё остальное — в зелёный.

**Случайность честная.** Выбор делает `crypto.getRandomValues`, а не
`Math.random`: результат не зависит от предыдущих прокруток. Остановка
дополнительно смещается внутри сектора (до 35% от его полуширины) —
без этого стрелка всегда вставала бы ровно в центр, и это выглядело бы
подделкой.

Вся арифметика вынесена в `core.js` (`randomUnit`, `rouletteIndex`,
`rouletteStopAngle`) и покрыта тестами: границы диапазона, равномерность
на 60 000 прогонов, попадание в нужный сектор.

При системной настройке «меньше движения» колесо не крутится — результат
появляется сразу.

## Шахматы

Раздел «Шахматы» в меню: игра с одногруппником. Создатель играет белыми
и ходит первым.

**Как пригласить.** Нажмите «Создать партию», затем «Пригласить» —
откроется выбор чата в Telegram. Ссылка ведёт в бота с параметром
`/start <id партии>`: бот сажает приглашённого за чёрных и присылает
кнопку «Открыть доску». Соперник получает уведомление, что игра началась.

**Как ходить.** Нажмите на свою фигуру — доступные клетки подсветятся
точками, а взятия кольцами. Нажмите на клетку. Пешка на последней
горизонтали спросит, во что превратиться.

Свои фигуры доступны для нажатия, только когда ход ваш; чужие и
недоступные клетки выключены. Но это удобство, а не защита: **ходы
всё равно проверяет сервер** через `python-chess`, и прислать
произвольный ход не выйдет.

**Кто есть кто** определяется подписью Telegram: мини-апп отправляет
`initData` заголовком `X-Telegram-Init-Data`, сервер проверяет
HMAC-SHA256 секретом из токена бота.

**Обновления.** Пока меню открыто, приложение опрашивает состояние раз
в 2,5 секунды, поэтому ход соперника появляется сам. Опрос останавливается
при закрытии меню — лишних запросов нет.

**Память.** Идентификатор партии хранится в `localStorage`, поэтому доска
восстанавливается после перезагрузки страницы.

Настройки в `assets/js/config.js`:

```js
window.CHESS = {
  enabled: true,
  bot: "pprsd23_bot",   // из него собирается ссылка-приглашение
};
```

Если переименуете бота в BotFather — поправьте `bot` здесь.

### Важно: нужен Upstash

Без внешнего хранилища партии лежат в памяти процесса и **исчезают при
каждом перезапуске Render** — а он перезапускается и при засыпании, и при
каждом деплое. Тогда соперник увидит «Партия больше недоступна».

Подключение описано в корневом `README.md`, раздел «API шахмат».
Проверить: `GET /api/chess/status` должен показать `"persistent": true`.

## Шаг 1. Узнать адрес API

Разверните бота на Render (см. корневой `README.md`) и скопируйте адрес
сервиса, например `https://schedule-bot-a1b2.onrender.com`.

Проверить, что API отвечает:

```bash
curl https://schedule-bot-a1b2.onrender.com/health
```

Первый запрос может занять до минуты — бесплатный Render просыпается.

## Шаг 2. Указать адрес в config.js

```js
window.SCHEDULE_API_BASE = "https://schedule-bot-a1b2.onrender.com";
```

Без слэша на конце. Адрес можно переопределить и без правки файла —
параметром в ссылке (удобно для проверки):

```
https://peskovsky18.github.io/-schedule-bot/?api=https://schedule-bot-a1b2.onrender.com
```

## Шаг 3. Опубликовать на GitHub Pages

Раньше приложение жило на Netlify. Оттуда пришлось уехать: у команды
закончились бесплатные кредиты, и **production-деплои приостановились** —
сайт остался жив, но новые версии перестали публиковаться. У GitHub Pages
для публичного репозитория нет кредитов, которые могут кончиться.

Публикуется папка `miniapp` в ветку `gh-pages`:

```bash
./deploy_pages.sh
```

Скрипт собирает ветку напрямую из объектов git, поэтому рабочая копия
не трогается: не нужно переключать ветки и ничего не теряется.

**Настройка делается один раз:** на GitHub → **Settings** → **Pages** →
Source: **Deploy from a branch**, ветка `gh-pages`, папка `/(root)` → Save.
После этого сайт живёт по адресу
`https://<владелец>.github.io/<репозиторий>/`.

Важно: **запускайте `deploy_pages.sh` после каждого изменения мини-аппа** —
в отличие от Netlify, здесь публикация не запускается сама. И поднимайте
`?v=N` у скриптов и стилей в `index.html`: своих заголовков кэша GitHub
Pages не поддерживает, а номер версии заставляет браузер и Telegram
взять свежий файл.

### Если понадобится вернуться на Netlify

Файлы `netlify.toml` и `_headers` оставлены и рабочие: конфигурация
прежняя, публикуется та же папка `miniapp`. Достаточно снова подключить
репозиторий.

## Шаг 4. Подключить к Telegram

Нужен бот-владелец приложения. Проще всего — автоматически: укажите на Render
переменную `MINIAPP_URL` с адресом приложения, и бот при старте сам поставит
кнопку меню «Расписание». Если она не появилась, перезапустите сервис
(**Manual Deploy → Restart**).

Если переменная не задана, бот берёт запасной адрес из кода
(`DEFAULT_MINIAPP_URL` в `bot.py`) — так кнопка работает сразу после
переезда. Своё значение всегда важнее.

Вручную через [@BotFather](https://t.me/BotFather):

1. `/mybots` → выберите бота → **Bot Settings** → **Menu Button** →
   **Configure menu button** → вставьте адрес приложения.
2. Либо `/newapp`, если хотите отдельное приложение со своей иконкой и
   короткой ссылкой вида `https://t.me/ваш_бот/имя_приложения`.

**Требование Telegram: адрес должен быть HTTPS.** `github.io` подходит.
Проверить, что текущий адрес виден боту: `GET /api/chess/status` покажет
поле `miniAppUrl`.

## Локальный запуск

```bash
# 1. API (из корня репозитория)
TOKEN=123456:TEST PORT=8201 python bot.py

# 2. Статика
cd miniapp && python3 -m http.server 8202
```

Откройте `http://localhost:8202/?api=http://127.0.0.1:8201`.

Приложение работает и вне Telegram — SDK подключается только если доступен,
поэтому его удобно отлаживать в обычном браузере.

## Особенности

- **Кэш в localStorage.** Бесплатный Render засыпает, поэтому при открытии
  сразу показывается последнее сохранённое расписание, а свежее
  подгружается в фоне. При отсутствии связи выводится предупреждение,
  но расписание остаётся на экране.
- **Время по Москве.** «Сегодня» и «Завтра» считаются по `Europe/Moscow`,
  а не по часовому поясу телефона, — иначе расписание разъезжалось бы
  у тех, кто уехал или сменил пояс.
- **Кэш не более 5 минут** (`CACHE_TTL` в `parser.py`). Кнопка обновления
  в шапке запрашивает данные заново.
- **Ссылки на Moodle** открываются через `Telegram.WebApp.openLink`,
  иначе внешний сайт открылся бы внутри webview и приложение «потерялось».
- **Тема** берётся из `themeParams`, есть светлый и тёмный вариант.
