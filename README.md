# Schedule Bot — расписание РГПУ им. А. И. Герцена

Телеграм-бот, который показывает расписание занятий по данным
[guide.herzen.spb.ru](https://guide.herzen.spb.ru/schedule).

Кнопки: **📅 Сегодня**, **⏭ Завтра**, **📆 Неделя** (ближайшие 7 дней).
Для администратора доступна панель `/admin`: статистика, список
пользователей, рассылка и логи ошибок.

Есть также **[мини-приложение](miniapp/)** — то же расписание в виде
интерфейса внутри Telegram. Оно лежит в каталоге `miniapp` и публикуется
на Netlify, а данные берёт отсюда через `GET /api/schedule`.

## Как это работает

Бот работает через **webhook**: Telegram отправляет POST-запрос на сервер
при каждом сообщении, сервер отвечает. Постоянный процесс и long polling
для продакшена не нужны — но для локальной отладки polling поддерживается.

Расписание берётся со страницы `.../schedule/<ID>/by-dates`. Данные
разбираются из JSON внутри Livewire-снимка (`wire:snapshot`), где уже есть
готовые поля: дата, время начала и конца, предмет, тип занятия,
преподаватель, аудитория, примечание и ссылка на курс в Moodle.
Если снимок недоступен, включается резервный разбор HTML.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `TOKEN` | да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `WEBHOOK_URL` | для webhook | Публичный адрес сервиса, например `https://my-bot.onrender.com`. На Render можно не задавать: адрес автоматически берётся из `RENDER_EXTERNAL_URL` |
| `GROUP_ID` | нет | ID группы на сайте. По умолчанию `25111` (4об_ППРСД/23) |
| `GROUP_NAME` | нет | Название группы, например `4об_ППРСД`. Если задано, актуальный ID ищется автоматически |
| `ADMIN_ID` | нет | Telegram ID администратора. По умолчанию `439819918` |
| `MINIAPP_URL` | нет | Адрес мини-приложения на Netlify. Если задан, бот поставит кнопку меню, открывающую расписание |
| `ALLOWED_ORIGINS` | нет | Домен, которому разрешён доступ к `/api/schedule`. По умолчанию `*` — данные публичные, запись через API невозможна |
| `TELEGRAM_SECRET` | нет | Секрет для проверки, что запросы действительно от Telegram |
| `USE_POLLING` | нет | `1` — работать через long polling вместо webhook |
| `PORT` | нет | Порт для локального запуска, по умолчанию `8080` |

## API для мини-приложения

```
GET /api/schedule
```

Отдаёт только предстоящие дни, начиная с сегодняшнего (по московскому
времени). Параметров нет.

```json
{
  "ok": true,
  "group": { "id": "25111", "name": "4об_ППРСД/23", "institute": "...", "program": "..." },
  "today": "2026-10-06",
  "tomorrow": "2026-10-07",
  "timezone": "Europe/Moscow",
  "cache_age": 12,
  "days": [
    {
      "date": "2026-10-06",
      "weekday": "вторник",
      "human": "6 октября, вторник",
      "lessons": [
        {
          "time": "11:20–12:50",
          "subject": "Социально-педагогическая девиантология",
          "type": "практика",
          "teacher": "доц. Жданова Марина Алексеевна",
          "room": "ауд. 21я, корпус 11 (Мойка 48)",
          "note": "29.09-13.10",
          "subgroup": 0,
          "moodle": "https://moodle.herzen.spb.ru/course/view.php?id=40413"
        }
      ]

```

CORS-заголовки выдаются только для `/api/*`, вебхук они не затрагивают.

### Про `GROUP_ID` и `GROUP_NAME`

ID группы на сайте выдаётся на учебный год и **меняется каждое 1 сентября** —
именно поэтому расписание когда-то перестало работать. Надёжнее задать
`GROUP_NAME`: бот найдёт актуальный ID сам. Посмотреть название и ID своей
группы можно на [странице расписания](https://guide.herzen.spb.ru/schedule).

Указывайте название полностью (`4об_ППРСД` или `4об_ППРСД/23`) — сравнение
регистронезависимое и суффикс года отбрасывается. Если задать только
фрагмент вроде `ППРСД`, бот возьмёт первую подходящую группу, а это может
оказаться чужое расписание.

## Запуск локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Через long polling — webhook и публичный адрес не нужны
export TOKEN="ваш_токен"
export USE_POLLING=1
python bot.py
```

Проверить состояние сервиса: `GET /health` возвращает количество дней и пар
в расписании.

## Развёртывание

### Netlify не подходит

Netlify Functions работает на TypeScript, JavaScript и Go —
[Python-рантайма там нет](https://github.com/netlify/context-and-tools/blob/main/skills/netlify-functions/SKILL.md).
Кроме того, Netlify — serverless: постоянного процесса нет, диска нет,
а вызов ограничен по времени. Для бота на Python нужен хостинг с
долгоживущим процессом.

### Что подойдёт

| Хостинг | Особенность |
|---|---|
| **Render** | бесплатный тариф, Python из коробки. Минус: сервис засыпает при простое ~15 минут, первый запрос после паузы идёт 30–60 с |
| **Railway** | не засыпает, но бесплатный лимит ограничен |
| **Fly.io** | Docker, постоянно включён, нужна карта |
| **VPS** | полный контроль, платно |

### Развёртывание на Render

В репозитории лежит готовый `render.yaml` — Render настроит сервис сам.

1. Зайдите на [dashboard.render.com](https://dashboard.render.com) и
   авторизуйтесь через GitHub.
2. **New → Blueprint**, выберите репозиторий `-schedule-bot`.
3. Render прочитает `render.yaml` и попросит ввести `TOKEN` — значение
   помечено `sync: false`, поэтому оно не хранится в репозитории.
4. Нажмите **Apply**. После сборки сервис будет доступен по адресу вида
   `https://schedule-bot.onrender.com`.

Адрес указывать вручную не нужно: Render задаёт `RENDER_EXTERNAL_URL`, и бот
берёт его оттуда, регистрируя webhook при старте. Убедиться, что всё
поднялось, можно открыв `https://<ваш-сервис>.onrender.com/health`.

Файл `Procfile` делает то же самое, если вы предпочитаете создать сервис
вручную (**New → Web Service**), без Blueprint:

```
gunicorn bot:app --bind 0.0.0.0:$PORT --workers 1 --threads 4
```

Достаточно одного воркера: webhook регистрируется один раз, в фоновом
потоке при старте, поэтому старт не зависит от доступности Telegram.

Чтобы бесплатный сервис не засыпал, можно пинговать `/health` раз в
10–14 минут через cron-job.org или UptimeRobot.

Пинговать стоит именно `/health`: он отвечает мгновенно из кэша и не
обращается к сайту университета.

### Проверка после деплоя

```bash
TOKEN="ваш_токен" python check_deploy.py
```

Скрипт проверяет, что токен действителен, webhook зарегистрирован и
указывает на ваш сервис, нет ошибок доставки, а `/health` отвечает и
расписание разобрано. Токен при этом никуда не отправляется, кроме
самого Telegram.

### Если деплой упал

**`Exception: TOKEN is not set`**

Сборка прошла, но сервис не запустился: переменная окружения не задана.
Самая частая причина — сервис создавали вручную (**New → Web Service**),
а не через Blueprint: в этом случае `render.yaml` не применяется совсем,
и переменные надо задавать руками.

Исправление — в панели Render: сервис → **Environment** → **Add Environment
Variable** → `TOKEN` = токен от @BotFather → **Save**. Render перезапустит
сервис сам.

Важная деталь про Blueprint: переменные с `sync: false` Render запрашивает
**только при первом создании** сервиса. При последующих обновлениях
Blueprint такие переменные игнорируются, и их нужно добавлять вручную.

**Порт не открывается, health check не проходит**

Раньше настройка webhook выполнялась при импорте модуля, а gunicorn на
Render работает с `--preload` — то есть до открытия порта. Недоступность
Telegram задерживала старт на 30 секунд. Сейчас настройка идёт в фоновом
потоке, и старт от сети не зависит. Если видите такую ошибку на старом
коммите — обновите код.

**Сервис поднялся, но бот не отвечает**

Смотрите логи: должна быть строка `[WEBHOOK] зарегистрирован: ...`. Если
её нет, проверьте `TOKEN` и что `RENDER_EXTERNAL_URL` не пустой.

## Ограничения

- **`users.json` не переживёт перезапуск** на бесплатном хостинге: диск там
  эфемерный. Список пользователей для рассылки будет обнуляться. Ошибка
  записи не ломает бота — `/start` продолжит работать. Для постоянного
  хранения нужно внешнее хранилище (Redis, Postgres или GitHub Gist).
- **Расписание кэшируется на 5 минут** (`CACHE_TTL` в `parser.py`).
- Разбор зависит от структуры сайта. Если вёрстка изменится, бот
  переключится на резервный разбор HTML, а в логах появится
  `[PARSE] JSON недоступен`.
